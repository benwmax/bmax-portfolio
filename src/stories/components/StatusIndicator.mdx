# StatusIndicator

Availability signal for the AI chat assistant — 7px dot, IBM Plex Mono 10px uppercase. Renders **below** ChatInput, never inside it. Online state blinks; offline state is static and dropped to disabled-text.

## States

### Online

Default state. Blinking green-bright dot signals readiness — same color as the cursor blink and input caret.

<Canvas of={StatusStories.Online} />

### Offline

API unreachable or backend down. Dot and label both drop to text-disabled.

<Canvas of={StatusStories.Offline} />

### Reserved states

Warning and Error are available programmatically but not shown by default in the chat widget.

<Canvas of={StatusStories.Warning} />
<Canvas of={StatusStories.ErrorState} />

## Do's

- **Render below ChatInput.** Never nest it inside the input component.
- **Use standard labels.** `ONLINE · assistant ready` / `OFFLINE · responses unavailable`.
- **Keep online blink enabled.** `blink` defaults to `true` for online — the blink is the readiness signal.

## Don'ts

- **Don't use "offline" for loading.** A request in-flight is still "online" — loading is an active state.
- **Don't show error state by default.** It surfaces programmatically on API failure only.

## AI guidance

Availability signal for the AI chat assistant. Renders below ChatInput — never inside it. Online = green-bright blinking. Offline = text-disabled, no blink. Warning and Error are reserved states.

**Content rules**
- Labels are always uppercase.
- Standard online label: `ONLINE · assistant ready`.
- Standard offline label: `OFFLINE · responses unavailable`.
- `blink` defaults to `true` for `status='online'` — do not override.

**Avoid**
- Don't render StatusIndicator inside the ChatInput component — it goes below.
- Don't use `offline` for a loading/in-flight state — loading is still `online`.
- Don't set `blink={false}` for the online state — the blink is the readiness signal.
