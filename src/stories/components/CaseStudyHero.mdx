## Do's

- **Write `title` as a problem statement.** "Modernizing X without Y" / "Making X learnable."
- **Use `accent={true}` for hard numbers only.** `$1B`, `+23%`, `+4–6%`, `< 3 mo.`
- **`subtitle` sets up the context** — 2–4 sentences, the problem not the solution.
- **Omit outcome cells entirely** when real data doesn't exist yet.

## Don'ts

- **Don't write `title` as a project description.** "Redesigned the USAA P&C experience" is wrong.
- **Don't put `accent={true}` on role or method values.** Only hard numbers get the green treatment.
- **Don't list more than 2 accent stats.** Four green cells dilutes the impact.
- **Don't pass empty placeholder stats.** Omit those cells — the grid flexes.

## AI guidance

Case study page header. The H1 (`title` prop) is always a problem statement, never a project description. `accent: true` on meta cells is reserved for hard numbers only.

**Content rules**
- `title` must be a problem statement: `"Modernizing X without Y"`, `"Making X learnable"`. Never write it as a project description.
- `subtitle`: one paragraph, 2–4 sentences setting up the problem context — not the solution.
- `accent: true` only for hard numbers: `"$1B"`, `"+23%"`, `"+4–6%"`, `"< 3 mo."`.
- Standard meta cells (role, method) use no accent.
- Target: 4 meta cells (role, method, 2 outcome stats). Can flex to 2 cells if outcomes are unavailable — omit those cells entirely.

**Avoid**
- Don't use `accent: true` for non-numeric values like `Lead UX Designer` or method names.
- Don't list more than 2 accent stats — four green cells dilutes the impact.
- Don't pass empty placeholder outcome stats — omit those cells and the grid flexes.
